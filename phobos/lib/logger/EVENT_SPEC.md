# PHOBOS Logger — Event Specification

Version: 1.0

---

# 1. Purpose

The PHOBOS Logger is a system-wide security and activity
monitoring subsystem.

It records relevant activities occurring on the host system,
independent of whether the activity was caused by PHOBOS itself.

The collected events are later used for:

- activity history
- security analysis
- anomaly detection
- security alerts
- severity ranking
- security summaries
- graphical visualization

---

# 2. Event Structure

Every event must contain the following fields.

| Field | Type | Required | Description |
|---|---|---:|---|
| `id` | string | yes | Unique identifier of the event |
| `timestamp` | ISO 8601 | yes | Time at which the event occurred |
| `category` | enum | yes | Type of event |
| `action` | enum | yes | Specific action |
| `user` | string | yes | User involved in the event |
| `source` | string | no | Source of the action |
| `target` | string | no | Target of the action |
| `device` | string | no | Device involved in the event |
| `status` | enum | yes | Result of the action |
| `severity` | enum | yes | Security relevance |
| `details` | string | no | Additional information |

---

# 3. Event ID

Every event receives a unique identifier.

Example:

id=01K7EXAMPLE123

The ID must uniquely identify one event.

---

# 4. Timestamp

The timestamp uses ISO 8601.

Example:

2026-10-08T20:15:32+02:00

The timestamp represents the time at which the
observed event occurred, not necessarily the time at
which PHOBOS processed it.

---

# 5. Categories

## 5.1 FILE

File system activities.

Actions:

- CREATE
- COPY
- MOVE
- DELETE
- MODIFY
- RENAME
- READ
- WRITE

---

## 5.2 DRIVE

Storage device activities.

Actions:

- CONNECT
- DISCONNECT
- MOUNT
- UNMOUNT

Examples:

- USB drives
- external HDDs
- external SSDs
- removable storage

---

## 5.3 AUTH

Authentication activities.

Actions:

- LOGIN_SUCCESS
- LOGIN_FAILED
- LOGOUT
- SUDO_SUCCESS
- SUDO_FAILED

---

## 5.4 USER

User and group management.

Actions:

- USER_CREATED
- USER_DELETED
- USER_MODIFIED
- GROUP_ADDED
- GROUP_REMOVED

---

## 5.5 PERMISSION

Permission and ownership changes.

Actions:

- PERMISSION_CHANGED
- OWNER_CHANGED
- ACL_CHANGED

---

## 5.6 PROCESS

Process activities.

Actions:

- START
- STOP
- CRASH

---

## 5.7 NETWORK

Network activities.

Actions:

- CONNECTION
- DISCONNECTION

Additional network actions may be added later.

---

## 5.8 SYSTEM

System-level activities.

Actions:

- BOOT
- SHUTDOWN
- REBOOT
- SERVICE_STARTED
- SERVICE_STOPPED
- CONFIG_CHANGED

---

## 5.9 SECURITY

Security events generated by the PHOBOS
analysis subsystem itself.

Actions:

- ANOMALY_DETECTED
- INTEGRITY_FAILURE
- TAMPERING_DETECTED
- SUSPICIOUS_ACTIVITY

---

# 6. User

The `user` field identifies the user associated
with the event.

Examples:

user
root
alice

For system-generated events where no user can be
identified:

SYSTEM

# 9. Device

The device associated with the event.

Examples:

MGS_SSD

/dev/sdb1

USB_DRIVE

If no device is involved:

---

# 10. Status

The result of the observed action.

Allowed values:

- SUCCESS
- FAILED
- DENIED

---

# 11. Severity

Severity describes the security relevance of an event.

Allowed levels:

- INFO
- LOW
- MEDIUM
- HIGH
- CRITICAL

Severity may initially be assigned by event rules
and may later be increased or decreased by the
anomaly detection system.

---

that does not fit into the standardized fields.

# 14. Security Summary

The Logger provides a summarized view of important
events within a selected time range.

Supported time ranges will include:

- last hour
- last 6 hours
- last 24 hours
- last 7 days
- last 30 days
- custom time range

Events are ranked by severity.

Priority:

CRITICAL
HIGH
MEDIUM
LOW
INFO

Events with the same severity are sorted by timestamp.

---

# 15. Alerts

Alerts are generated when an event or combination
of events requires user attention.

An event may appear in the Security Summary without
creating an alert.

Example:

A USB drive being connected may be a MEDIUM event
without generating an alert.

Multiple failed logins combined with unusual file
activity may generate a HIGH or CRITICAL alert.

---

# 16. Anomaly Detection

The Logger will analyze events for unusual behavior.

Examples:

- repeated failed login attempts
- unusual file activity
- unusual external storage activity
- unexpected permission changes
- unusual process activity
- unusual network activity
- combinations of otherwise harmless events

Anomaly detection may generate new SECURITY events.

Example:

category=SECURITY
action=ANOMALY_DETECTED

---

# 17. Graphical Representation

The PHOBOS GUI will provide:

- event timeline
- security summary
- alerts
- severity ranking
- event filtering
- time-range filtering
- anomaly information

Severity should be visually distinguishable.

Suggested representation:

INFO      → neutral
LOW       → green
MEDIUM    → yellow
HIGH      → orange
CRITICAL  → red
